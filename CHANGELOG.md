# Changelog

## 1.0.0

- Initial release of Masterly.NightShift.
- Packages: `Masterly.NightShift`, `Masterly.NightShift.Core`, `Masterly.NightShift.SqlServer`, `Masterly.NightShift.NetCore`, `Masterly.NightShift.AspNetCore`.
- Targets `netstandard2.0`, `net8.0` and `net10.0`.
- Licensed `MIT AND LGPL-3.0-or-later`: code written for Masterly.NightShift is MIT, code derived from Hangfire stays LGPL. The packages carry both license texts.
- JSON through System.Text.Json; no Newtonsoft.Json dependency. `UseSerializerSettings` and `UseRecommendedSerializerSettings` take `JsonSerializerOptions`. Data written by Newtonsoft-based versions, including `$type` states and arguments, stays readable.
- Reflection-free job invocation, interceptors, concurrency control, batches, fan-in continuations, run windows, a redesigned dashboard with live monitoring and insights, drain mode, Prometheus metrics, alerts, an audit log and OpenTelemetry-compatible telemetry. See `docs/whats-new-next.md`.
- ASP.NET Core health checks (`AddHealthChecks().AddNightShift()`), `MapNightShiftHealth`/`MapNightShiftMetrics`, server options from configuration (`AddNightShiftServer(IConfiguration)`), Discord alerts, a testing guide and a web sample.
- The activity feed is opt-in (`UseActivityFeed()`) and written after commit, so it no longer slows down state changes.
- Fixes behaviour inherited from Hangfire 1.8.25, such as running the exact overload of a job method, clearer failure reasons when a job can't be loaded, SQL Server options that schema auto-detection no longer overrides, clear errors instead of silent truncation for over-long values, batched purges, dashboard CSRF protection when antiforgery isn't registered, and loggers that follow a provider set later. See `docs/breaking-changes.md`.
- .NET Framework (and .NET 6/7) apps get the `netstandard2.0` build, which is now tested on .NET Framework 4.8. That found and fixed two problems: a job failed after running when a scoped dependency only implemented `IAsyncDisposable`, and projects on C# 7.3 failed to build with CS8370 in the generated `NightShiftJobInvokers.g.cs`. The hosted services there now also wait for `IHostApplicationLifetime.ApplicationStarted` when the host provides it.
- Start and end dates for recurring jobs (`RecurringJobOptions.StartAt`/`EndAt`), an opt-in retention period for failed jobs (`[ExpireAfter(..., IncludeFailed = true)]`, `UseFailedJobRetention`), a logging scope with the job id and name around every job (`AddNightShiftServer`), `CircuitBreakerAttribute.ExceptOn`/`OnlyOn`, a `retry_later` telemetry outcome, and a Microsoft Teams webhook format.
- `Masterly.NightShift.NetCore` needs Microsoft.Extensions 8.0.x on `netstandard2.0` and `net8.0` (10.0.x only on `net10.0`), so .NET 8 apps keep their runtime's stack.
- A third review added `BatchJob.Cancel`/`RequeueFailed`, `JobStorage.RequeueFailedJobs`, `GetJobState`, `TryGetResult<T>`, `ThrottleAttribute.GetSlots`/`Release`, repeatable `[RateLimit]` for tiered limits, connection string names from `app.config` on .NET Framework, a page on job progress, console and checkpoints, and fixed, among others: Hangfire-stored collection arguments that couldn't be read after the migration, structs losing their values, a fetched job that could stay invisible after a connection drop, succeeded jobs failed by a storage error while releasing a throttle slot or writing a console line, `tonight at 9` meaning 09:00, recurring runs lost when enqueuing one failed, the dashboard's catalog form and live polling, and the Prometheus family name clash.
- A second review fixed, among others: job arguments losing members equal to their `[DefaultValue]`, job payloads unreadable under a snake_case naming policy, the dashboard's Pause buttons, same-named job types sharing concurrency slots, the circuit breaker counting lock timeouts, SQL Server installs with non-Latin schema names, servers listening to 64 or more queues, and the packed MSBuild props file being ignored by git. See `docs/breaking-changes.md`.
