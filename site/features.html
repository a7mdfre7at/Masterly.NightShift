Jobs and scheduling

Every job type

Fire-and-forget, delayed, recurring and continuation jobs, all persisted to storage and run by workers in any number of servers.

Schedules in plain English

TimeText.Parse understands relative phrases, times of day, weekdays, “next week”, “end of day/month” and ISO dates. Cron.FromText does the same for recurring jobs, and Cron.Builder() builds validated CRON expressions fluently.

BackgroundJob.Schedule(() => SendReport(), "tomorrow at 9am");
RecurringJob.AddOrUpdate("digest", () => SendDigest(), Cron.FromText("weekdays at 7:30"));
var cron = Cron.Builder().EveryMinutes(15).Between(9, 17).OnWeekdays();

Pause, resume and edit recurring jobs

A paused job keeps its definition, stays paused across redeploys, can still be triggered by hand, and resumes from now without catching up. Edits also work from the dashboard.

RecurringJob.Pause("digest");
RecurringJob.UpdateSchedule("digest", "every 2 hours between 8 and 18 on weekdays");

Recurring job manifests

Export every recurring job as JSON, keep it in source control and apply it in another environment. Applying is idempotent, and entries that fail are reported without stopping the others.

var json = RecurringJobManifest.Export();
RecurringJobManifest.Apply(json, prune: true);   // remove the ones not listed

Fan-in continuations

A job can wait for a set of parents in the Awaiting state, for all of them or for the first. If a parent vanishes from storage it counts as deleted, so a continuation never waits forever.

BackgroundJob.ContinueJobWithAll(parts, () => Merge());
BackgroundJob.ContinueJobWithAny(parts, () => NotifyFirst());

Batches

Jobs created inside StartNew belong to a batch with its own progress page. ContinueWith runs once every job in the batch has finished.

var batchId = BatchJob.StartNew(batch =>
{
    foreach (var region in regions) batch.Enqueue(() => Export(region));
}, "Regional exports");

BatchJob.ContinueWith(batchId, () => Merge());

Run windows and blackouts

Restrict when a job may start. A job picked up at the wrong time is rescheduled for the window’s next start, with the reason in its history.

[RunWindow("22:00-06:00", "Europe/Berlin")]
[Blackout("02:00-04:00")]
public Task Reindex() { ... }

Concurrency and reliability

Throttle, rate limit and circuit breaker

Limit concurrency with a distributed semaphore, cap calls per time window, and stop calling a failing dependency. When a job cannot run, Action decides whether it is rescheduled (the default), waits, or is skipped. Open circuits show on the Insights page and can be reset there.

[Throttle("tenant-{0}", MaxConcurrency = 2)]
[RateLimit("sms", limit: 100, perSeconds: 60)]
[CircuitBreaker("payments", failureThreshold: 5, windowSeconds: 60, openSeconds: 120)]
public Task Send(string tenant, Message message) { ... }

Duplicate prevention

A second copy of a pending job is refused (Enqueue returns null) or replaces the first. The check runs at creation time under a distributed lock.

[PreventDuplicates("reindex:{0}")]
public Task Reindex(string index) { ... }

Retry later

A job can say exactly when it wants to run again. The request does not use up a retry attempt, and it is still bounded by MaxRetryLaterRequests.

throw new RetryLaterException(TimeSpan.FromMinutes(1), "Rate limited by the partner API");

Resumable jobs

Checkpoints survive retries. Resume skips a step whose checkpoint is already recorded, so a job that crashed in step three restarts at step three.

console.Resume("download", () => Download(file));
console.Resume("parse", () => Parse(file));
console.Resume("save", () => Save());

Interceptors

Interceptors wrap the method call itself: they see the activated instance, can replace arguments, and run inside the performer. Built in: [JobTimeout], [RetryInProcess] and [LogInvocation]. Apply them as attributes or globally with UseJobInterceptor.

public sealed class MeasureAttribute : AsyncJobInterceptorAttribute
{
    protected override async Task<object?> InterceptAsync(JobInvocation invocation)
    {
        var stopwatch = Stopwatch.StartNew();
        var result = await invocation.ProceedAsync();
        invocation.Context.Console.WriteLine($"took {stopwatch.ElapsedMilliseconds} ms");
        return result;
    }
}

Deadlines and per-method retention

[Deadline] records when a job should be done by, and flags overdue jobs without canceling anything. [ExpireAfter] keeps a method’s finished jobs for as long as you choose instead of the storage-wide default.

[Deadline("00:10:00")]
[ExpireAfter(days: 30)]
public Task Export() { ... }

Observability

Live console and progress

Jobs can take an injected IJobConsole to report progress, write levelled lines and mark checkpoints. The job page shows them live. Pass null for the parameter when enqueueing; the server injects it.

public async Task Import(string file, IJobConsole console)
{
    console.Checkpoint("download");
    await Download(file);
    console.SetProgress(50, "halfway");
    console.WriteLine(JobConsoleLevel.Warning, "3 rows skipped");
}

Job insights

UseJobInsights() records runs, failures and the last 200 durations per method, giving failure rates, median, p95 and max, a trend, and an ETA for running jobs.

GlobalConfiguration.Configuration.UseJobInsights();

Tags

Find jobs by what they are about. A tag is a word or a template over the arguments, and the command palette searches tags.

[Tag("customer:{0}"), Tag("export")]
public Task Export(string customer) { ... }

JobTags.Add(jobId, "priority:high");   // after the fact

Alerts and webhooks

An alert is raised when a job finally fails, a deadline is missed or a circuit breaker opens. UseWebhookAlerts posts them as JSON or as a Slack, Mattermost or Discord compatible message, and UseAlerts(IAlertSink) plugs in anything else.

GlobalConfiguration.Configuration.UseWebhookAlerts("https://hooks.example.com/...", o => o.Format = WebhookFormat.Slack);

Redacted arguments

A parameter marked [Redacted] is masked everywhere the dashboard shows arguments. The value is still stored with the job, so redaction protects dashboard viewers, not the storage.

public Task Connect(string host, [Redacted] string password) { ... }

Telemetry, health and metrics

OpenTelemetry-compatible traces and metrics, a /health endpoint for probes and a Prometheus /metrics endpoint. See Configuration.

Operations

Drain mode and pausing

Pause all processing, one queue or one server without stopping anything: running jobs finish and new ones are handed back. Do it from the dashboard or from code.

DrainMode.Enable(connection, "deploy 2.0");
DrainMode.PauseQueue(connection, "emails", "smtp outage");
DrainMode.PauseServer(connection, "web-1", "deploying");

Keep-alive

An optional background process requests the host’s own URL at an interval so an idle timeout, such as IIS’s, does not stop the server.

services.AddNightShiftKeepAlive();

Maintenance

The Servers page can clear all jobs or reset the storage, when the storage supports it. SQL Server does.

Platform

Reflection-free job invocation

Job methods are performed by a cached JobInvoker. A source generator inside the Core package emits direct typed calls for the methods you enqueue. Without one, a compiled expression delegate is used, and reflection is the last resort. Mark classes that other assemblies enqueue with [GenerateJobInvokers]. To skip generation in a project, set the MSBuild property NightShiftDisableJobInvokerGeneration to true.

[GenerateJobInvokers]
public class ReportJobs { public Task Build(int reportId) { ... } }

Pluggable storage

JobStorage is the entry point every storage implements. Newer optional capabilities are advertised as features rather than new interface members. SQL Server storage is included, with sliding-invisibility-timeout fetching and a pluggable queue provider.

Filters and extensibility

Client, server, state-election and state-apply filters are the main extension mechanism, discovered from attributes and the global filter collection. Job activation plugs into your DI container.

Data compatibility levels

SetDataCompatibilityLevel controls the serialized payload format so servers on different versions can share storage. Levels are Version_110, Version_170 and Version_180.

Target frameworks

netstandard2.0, net8.0 and net10.0. Classic ASP.NET and OWIN hosting are not supported.
