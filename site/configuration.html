Configuration

Configure Masterly.NightShift: SQL Server storage, data compatibility levels, telemetry, Prometheus, health, keep-alive, drain mode, authorization, read-only mode and base path.

Storage: SQL Server

Pass a connection string, and optionally SqlServerStorageOptions. The schema is installed and migrated on start when PrepareSchemaIfNecessary is on (the default). Both Microsoft.Data.SqlClient and System.Data.SqlClient are supported.

config.UseSqlServerStorage(connectionString, new SqlServerStorageOptions
{
    SlidingInvisibilityTimeout = TimeSpan.FromMinutes(5),
    PrepareSchemaIfNecessary = true
});

Other storages plug in through JobStorage.

Data compatibility levels

The level decides the serialized payload format, so older servers can still process jobs. Set it once, before anything else uses the storage. The supported values are Version_110 (the default when you set nothing), Version_170 and Version_180.

GlobalConfiguration.Configuration
    .SetDataCompatibilityLevel(CompatibilityLevel.Version_180);

Telemetry (OpenTelemetry-compatible)

UseTelemetry() is available on .NET 8 and later. It registers a global filter that emits create and process spans from the Masterly.NightShift activity source and nightshift.job.* instruments from the Masterly.NightShift meter. The creating trace context travels with the job, so the processing span joins the same trace. Nothing is recorded unless a listener is attached.

services.AddNightShift(config => config
    .UseTelemetry()
    .UseSqlServerStorage(connectionString));

// With the OpenTelemetry SDK, listen to the source and the meter:
//   .AddSource("Masterly.NightShift")
//   .AddMeter("Masterly.NightShift")

Prometheus endpoint

GET {dashboard path}/metrics, for example /nightshift/metrics, returns the Prometheus text format: jobs by state, queue lengths, servers, recurring jobs and late ones, the paused flag, health status, per-method run counts and duration percentiles, and per-queue wait percentiles and throughput. Metric names start with nightshift_. The endpoint is subject to the dashboard’s authorization filters.

Health endpoint

GET {dashboard path}/health answers 200 with healthy or degraded, and 503 with unhealthy when storage is unreachable or no server is alive. It checks storage latency, live and stale servers, queues nobody listens to, paused processing, and late or error-disabled recurring jobs. {dashboard path}/ping is a storage-free liveness URL. Both are subject to the dashboard’s authorization filters, so a probe from another host needs an authorization setup that allows it.

Keep-alive

IIS stops an idle worker process after 20 minutes, and the NightShift server inside it stops too. The real fix is the pool settings (startMode="AlwaysRunning", preload, idle timeout 0) or a Windows Service or worker host. As a safety net, the keep-alive process requests a URL every five minutes by default.

services.AddNightShiftKeepAlive();   // requests its own /nightshift/ping

// Behind IIS: give the public URL
services.AddNightShiftKeepAlive(o => o.Url = "https://jobs.example.com/nightshift/stats");

KeepAliveOptions also has Interval, Timeout and LogFailures. Without dependency injection, pass a KeepAliveProcess to the BackgroundJobServer constructor. The Servers page shows its status.

Drain mode

Drain mode stops workers from starting new jobs while running ones finish. Switch it on from the Servers page (“Pause processing”) or in code. Workers hand new jobs back to Scheduled for 30 seconds and look again. The same exists per queue and per server.

DrainMode.Enable(connection, "deploy 2.0");
DrainMode.PauseQueue(connection, "emails", "smtp outage");
DrainMode.PauseServer(connection, "web-1", "deploying");

Dashboard authorization

By default the dashboard accepts local requests only (LocalRequestsOnlyAuthorizationFilter). Replace that with your own filters, or use an ASP.NET Core authorization policy:

// An ASP.NET Core policy
app.MapNightShiftDashboardWithAuthorizationPolicy("NightShiftAdmins");

// Or your own filter
app.MapNightShiftDashboard("/nightshift", new DashboardOptions
{
    Authorization = new[] { new MyAuthorizationFilter() }   // IDashboardAuthorizationFilter
});

IDashboardAsyncAuthorizationFilter is available through AsyncAuthorization. Dashboard actions are recorded in the audit log under the authenticated user.

Read-only mode

Show the dashboard without allowing changes, for everyone or only for some users.

new DashboardOptions
{
    IsReadOnlyFunc = context => !context.GetHttpContext().User.IsInRole("Operators")
}

GetHttpContext() is the ASP.NET Core extension on DashboardContext.

Base path and other options

The default path is /nightshift. Pass another pattern to MapNightShiftDashboard or UseNightShiftDashboard. Other DashboardOptions properties:

  • AppPath: target of the “Back to site” link, or null to hide it.
  • PrefixPath: a prefix put in front of the dashboard’s generated links.
  • DashboardTitle, DefaultRecordsPerPage, StatsPollingInterval (milliseconds), DarkModeEnabled, DisplayStorageConnectionString.
app.MapNightShiftDashboard("/jobs", new DashboardOptions
{
    DashboardTitle = "Orders jobs",
    AppPath = "/"
});
