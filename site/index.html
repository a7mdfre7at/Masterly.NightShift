What you get

Background processing for .NET applications, with the tooling to watch it work.

Every kind of job

Fire-and-forget, delayed, recurring and continuation jobs, including fan-in continuations and batches.

Persisted to storage

Jobs live in pluggable storage, with SQL Server as the reference implementation.

Built-in dashboard

Live monitoring, a job catalog, insights, a wallboard, a worker timeline and an audit log.

Reflection-free invocation

A source generator emits typed calls for your job methods, with compiled and reflection fallbacks.

Concurrency control

Throttle, rate limit and circuit-break jobs, and keep duplicates out of the queue.

Plain-English schedules

Write every 2 hours between 8 and 18 on weekdays or tomorrow at 9am instead of CRON.

Operations ready

Health and Prometheus endpoints, OpenTelemetry-compatible telemetry, drain mode and webhook alerts.

Wide runtime reach

Targets netstandard2.0, net8.0 and net10.0, so .NET Framework 4.6.2+ and modern .NET both work.

See every feature

A few lines to start

Register storage, add the server, map the dashboard. Jobs are plain method calls: the lambda is turned into a stored job and run by a worker, in this process or another one.

Nothing is hosted for you and no separate service is required. The server runs inside your own application.

Read the full walkthrough

using Masterly.NightShift;
using Masterly.NightShift.SqlServer;

builder.Services.AddNightShift(config => config
    .UseSqlServerStorage(connectionString));
builder.Services.AddNightShiftServer();

var app = builder.Build();
app.MapNightShiftDashboard();   // /nightshift

BackgroundJob.Enqueue(() => Console.WriteLine("Hello, night shift!"));
RecurringJob.AddOrUpdate("digest", () => SendDigest(), Cron.FromText("weekdays at 7:30"));
BackgroundJob.Schedule(() => Close(), "end of month");

app.Run();

Why NightShift

See what is happening

A redesigned dashboard shows live progress, why a job is not running, and how jobs relate to each other, instead of leaving you to read logs.

Control it without a redeploy

Pause a queue, a server or all processing, edit recurring jobs, and run any job method from the Catalog page.

Safe by design

The dashboard only accepts local requests until you configure authorization, arguments can be redacted, and every dashboard action goes to an audit log.

Fits your storage

New features use only the hash, set, list, counter and job-parameter primitives every storage already implements.
