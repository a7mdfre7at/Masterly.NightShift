A dashboard that ships with the library

The dashboard is part of the package, with no separate service to run. It has a left sidebar with live counts for every job state, a top bar with a connection indicator that turns red when polling fails, and a theme switcher for system, light and dark. It works on narrow screens, where the sidebar collapses behind a menu button, and it is translated into 15 locales.

Map it with app.MapNightShiftDashboard(); the default path is /nightshift.

Pages

Overview

KPI tiles, charts, and a live feed of every state transition across the cluster.

Jobs

Lists per state with refresh and live reload, bulk actions, and Delete all.

Recurring jobs

Pause, resume, trigger and edit schedules, import and export manifests, and a Late badge for overdue ones.

Servers

Processes, queues served, hosting and keep-alive status, and pause switches.

Queues

Per-queue pause and resume, with wait times and drain estimates when insights are on.

Catalog

Every job method the generator found, with a form to run it now, later or on a schedule.

Batches

Progress bars for each batch, with requeue-failed and delete-unfinished.

Tags

Every tag with its job count, and the jobs behind it.

Insights

Failure rates, median, p95 and max per method, plus open circuit breakers.

Audit

The last thousand actions taken through the dashboard.

Live monitoring

The job page shows a progress bar, the job console and a checkpoint timeline as the job runs, with elapsed time. The Processing page shows every running job’s progress, and jobs that never report progress get an estimated bar based on past runs of the same method. A job running past its p95 is flagged as longer than usual.

Understanding a job

  • Diagnosis: answers “why isn’t it running?” for enqueued, scheduled, awaiting, processing and failed jobs, one sentence per finding, each with a severity and a link to the page that fixes it.
  • Lineage: draws the continuation graph around a job, coloured by state and linked to each job, limited to 40 jobs.
  • Time in each state: a bar showing how long a job waited, ran and sat in retries.
  • Failure clusters: the Failed page groups the latest 500 failures by exception type and method, with requeue-all and delete-all per cluster.
  • Notes and acknowledgements: leave findings for the next person, or acknowledge a failed job so the team sees it is being looked at.
  • Copy as C#: the statement that re-creates a job, and Run again with changes to fix one argument and run it again.

Insights, heatmap and forecast

The Insights page opens with the methods that need attention: a recent median at least twice the earlier one, a failure rate of 20% or more, or an unusually slow last run. Above it is an activity heatmap of the last seven days, hour by hour, shaded by finished jobs and red where failures outnumbered successes. Recurring jobs, Forecast lays every upcoming run for the next 24 hours or 7 days on one timeline and highlights slots where several jobs start within the same five minutes.

Wallboard and timeline

/wallboard is built for a wall display: no navigation, large numbers, a green, amber or red status pill, queues with their drain times, running jobs with predicted end, and an Attention list from the health checks. It refreshes every ten seconds and is always dark.

/timeline draws what every worker did in the last fifteen minutes, one lane per worker grouped by server, one bar per run, coloured by outcome. Outcomes are also distinguished by pattern, with a striped bar for runs still in progress.

Search, palette and keyboard

Open the command palette with Ctrl+K, / or the search button to find pages, a job by id, recurring jobs by name, and tags (tag:contoso). Type > for commands:

  • > pause processing and > resume processing
  • > pause queue emails
  • > resume server web-1
  • > requeue #4711 and > delete #4711
  • > wallboard and > timeline

On job lists, j and k move, x selects, Enter opens, r requeues and d deletes the selection. ? shows every shortcut, and g followed by a letter jumps to a page.

Watchlist and notifications

Watch on a job page adds it to a sidebar panel that follows its state on every page. When a watched job finishes, a toast appears and, if the browser allows it, a desktop notification. The list is stored per browser.

Exports

Every job list has Download CSV, up to 10,000 rows, with exception details for failures and spreadsheet formula characters neutralised. A job page has Export JSON with the method, arguments (redacted ones masked), full history, parameters, console and notes, ready to attach to a ticket.

Control from the dashboard

  • Pause and resume processing, a queue, or a single server.
  • Edit recurring job schedules in CRON or plain English, with the CRON explained under the editor.
  • Run any catalogued job, now, later or recurring.
  • Requeue or delete in bulk, and clear all jobs or reset storage from the Servers page where the storage allows it.

Every one of these is recorded in the audit log, and all of them can be switched off with read-only mode.
